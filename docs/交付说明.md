# CDE 工程压缩包交付说明

## 交付对象

- 文件名：`创新CDE 姜皓凯 1.zip`
- 工程基线：远端 `main`，最终整理提交 `c80369e755bb9ec1e3e8f9638dce62acbb1eb91f`；团队工程基线为 `308b6aa85893cbda447d392f140bb3cf34639694`
- 内容用途：老师查看源码、工程结构、创新实现、验证摘要和复现入口

压缩包顶层目录是 `创新CDE 姜皓凯 1/`，进入后可直接看到 `README.md`。README 第一屏给出教师导航、姜皓凯个人贡献和四条创新链路，源码和证据均使用仓库相对路径。

## 保留内容

1. `Exp9_源码_v文件/`：课程五级流水 SoC、UART 接口、板级顶层、约束、初始化输入和教师测试台。
2. `Cache/`：I/D Cache 集成源码、CPU、仲裁器、SRAM bridge、测试台、脚本、教师输入压缩副本和机器可读验证摘要。
3. `D-cache/`：独立 D-Cache 及其技术文档和测试入口。
4. `innovation_uart/`：UART RTL、固件、测试台和验证记录；保留 COE 初始化文件。
5. `vivado/`：创建工程、仿真、综合和 bitstream 操作脚本。
6. `Evidence/` 与 `artifacts/`：精选 PASS 日志、截图、manifest、SHA-256、验证 JSON 和可读技术说明。
7. `docs/`：教师验收导航、个人贡献、交付清单和复现说明。

## 为满足 200 MB 而清理的内容

以下是工具自动生成且可由脚本重新产生的文件，已从提交压缩包中移除：

- Exp8/Exp9 XSim `.wdb.part*` 波形分片及其他 `.wdb`、`.vcd`、`.wcfg` 文件；
- 所有 `build/`、Vivado 运行目录、`xsim.dir/`、`__pycache__/` 和编译出的仿真二进制；
- Evidence 中重复保存的 `mif/coe` 初始化副本，保留实际工程入口和 `Cache/fixtures/` 的带哈希输入；
- `Junwei_Jian's Exp1~Exp7/` 下的个人实验备份压缩包。该目录仍在远端 `main`，每个备份体积较大且不是创新 CDE 的运行依赖；
- `.git/`、`.DS_Store` 和本机日志缓存。

清理只发生在交付副本，不修改远端 `main` 的历史、源码和原始证据。保留下来的 `Important/Summary/`、截图、PASS 日志、manifest 和 SHA-256 足以定位结果；需要查看完整波形时，可在远端仓库或 Windows/Vivado 环境按相应工程脚本重新生成。

## 解压后的最短检查

```bash
cd '创新CDE 姜皓凯 1'
sed -n '1,220p' README.md
python3 Cache/tests/run_all.py --quick
python3 Cache/tests/run_cpu.py
python3 innovation_uart/sim/run_control.py
```

完整回归使用 `python3 Cache/tests/run_all.py`；UART 全部模式使用 `python3 innovation_uart/sim/run_regression.py --mode all`。若只阅读材料，先看 `docs/教师验收导航.md`，不需要生成任何 Vivado 目录。

## 体积验收

打包前统计提交副本的文件总量，打包后同时检查 ZIP 的字节数；最终 ZIP 必须小于 200 MB。压缩包内不含 Git 元数据，避免把版本对象和历史波形带入提交文件。
