## 具体实现内容

### I-Cache

- 每行 16 B，默认 256 组、2 路，支持 1/2/4 路配置。
- tag 比较、命中返回、miss 请求、四字回填和最后一个字旁路完整闭环。
- 优先选择无效路，其次按真 LRU 替换；管理和复位会重置有效位及替换状态。
- 请求寄存与查询/响应分阶段，使独立 I-Cache 在热命中时能够连续接受和返回请求。

### CPU 与公共接口

- 将固定一拍访存改为“地址接受＋实际完成”两阶段，CPU 只在真实 `data_ok` 后推进 load/store。
- 保存取指 PC 与响应的配对关系；跳转、异常和 CACOP 后丢弃已接受的旧响应，避免错认成新指令。
- store 只握手一次，年轻 store 在更老指令尚未提交或发生异常时不会修改缓存和外设。
- 用五来源轮转仲裁合并 I 回填、D 回填、D 写回和两侧 uncached 请求；整行传输的第四个字完成后才释放所有权。
- 对 `bfaf_xxxx` / `1faf_xxxx` 外设区域旁路，保留完整低位地址和原始字节使能；板级 data RAM 通过地址归一化保持别名一致。

### CACOP 与自修改代码

在 CPU 真实译码路径中接入六种课程教学 CACOP：I/D 初始化、按索引无效化或写回后无效化、按命中无效化或写回后无效化。管理指令等待更老指令提交，缓存完成后从本条 PC+4 重取指。验证程序按“D 写回无效化 → I 无效化 → 重新取指”顺序检查自修改代码，避免把缓存控制只做成未连接的接口。

## 公平性能对照

同一 CPU、同一程序、同一逐字主存模型，每字固定 8 拍；有缓存模式把 I/D 容量固定为各 512 B：

| 程序 | 无缓存 | 直接映射 | 两路 | 四路 |
| --- | ---: | ---: | ---: | ---: |
| 热点循环 | 13,121 | 3,196 | 3,196 | 3,196 |
| 同组双行冲突 | 13,121 | 14,499 | 3,285 | 3,285 |
| 冷启动＋自修改代码＋异常 | 1,297 | 1,399 | 1,399 | 1,399 |

这些数据同时呈现收益和代价：热点与同组冲突场景中缓存显著减少主存事务，直接映射冲突场景会因替换开销变慢，冷启动管理场景也没有收益。完整命中率、读写次数、低延迟课程桥对照和计数口径见缓存报告。
