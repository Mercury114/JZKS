## 从源码定位四项创新要求

### 1. 一路直接映射、I/D 均实现

在 `Cache/rtl/cache_icache.v` 和 `Cache/rtl/cache_dcache.v` 中将 `WAY_NUM` 设为 1；`Cache/tests/run_teacher.py --exp 9 --ways 1` 是教师 ex9 的直接映射入口。`cache_subsystem.v` 把 I/D 两侧接入同一条主存事务链路，`ENABLE_CACHE=0` 是同一 CPU 的无缓存对照。

### 2. Cache 指令

`Cache/rtl/cpu/id_stage.v` 译码 CACOP，`Cache/rtl/cache_subsystem.v` 路由管理请求，`cache_icache.v` 与 `cache_dcache.v` 分别完成初始化、无效化和写回路径。六种课程教学子集的编码、权限、完成条件和自修改代码顺序写在 `Cache/docs/缓存设计与测试报告.md` 第 7 节。

### 3. 多路组相连 Cache

I/D 两侧均支持 1/2/4 路，优先使用无效路，随后按真 LRU 选择替换路；D 侧替换脏行前以 128 bit 整行写回。`Cache/tests/run_all.py` 和 `Cache/docs/verification-results.json` 保留三种路数的独立结果。

### 4. Cache 流水化

I-Cache 在请求接受沿锁存 tag/index/word，下一阶段完成命中查询与响应；独立测试对连续接受和连续返回做检查。CPU 当前保留一笔未完成取指请求，D-Cache 为阻塞式，这是实现接口和验证报告中的明确架构口径。

## 验证结果如何解读

- `Cache/docs/verification-results.json` 的 30 项是本地 Icarus 结果，包含编译与运行两类检查；其中 528 次 CPU 运行、24 次整机 ISA 对照和 ex4～ex9 教师程序均由脚本独立生成期望值。
- `Evidence/UART/Important/Summary/pipeline-irq-verification.json` 的 34,362 项来自 UART 五级流水 SoC 的 Icarus 回归，另列 CSR、精确 IRQ、Vivado IRQ 和板级启动证据；UART 远程 FPGA 需要按文档重新上传 bit 后验收。
- `Evidence/AXI/Important/Summary/verification-results.json` 明确记录两个 Vivado XSim 测试台通过，以及未覆盖 burst、多 outstanding 和板级验证的范围。
- `Evidence/Full Exp (with Exp8 and Exp9)/Important/Summary/关键 PASS 输出汇总.md` 是 Exp4～Exp9 的本地教师程序 PASS 摘要。它与 UART 演示固件、Cache 回归和线上平台结果分开统计。

## 建议演示路线

1. 先打开 `Cache/docs/缓存设计与测试报告.md` 第 2、4、5、7、8 节，按系统图解释请求如何从 CPU 经过 I/D Cache、仲裁器和 SRAM bridge 完成。
2. 用 `python3 Cache/tests/run_all.py --quick` 或分别运行 `python3 Cache/tests/run_cpu.py`、`python3 Cache/tests/run_system.py`，再对照测试台定位一个命中、一个 miss、一次脏块写回和一次 CACOP。
3. 打开 `innovation_uart/sim/README_UART_SIM.md`，演示 `HELP`、`CODE A`、`START/TIME/STOP` 和 `IRQ ON/COUNT/OFF` 的硬件交互逻辑。
4. 最后阅读 `cache_axi_bridge.v` 及 AXI 摘要，说明 AR/R、AW/W/B 的握手顺序、窄写的 WSTRB 和响应检查。

## 阅读边界

课程官方 Exp9、Cache 集成 SoC、UART 演示 SoC 和 AXI 顶层是四个可复现入口，工程文件和固件分别保存。报告中的模块分工、课程实验结果和本仓库中的团队扩展验证可以互相印证，但应按各自证据文件的工具、日期和测试对象阅读。
