## 二、我完成了什么

### 1. I-Cache

- 完成指令读取、tag比较、命中返回、未命中请求与四字回填。
- 支持一路直接映射、两路和四路组相连；优先选择无效路，其余按真正LRU替换。
- 行大小16B，默认256组、2路，指令缓存容量8KiB。
- 加入请求寄存与查询/响应流水：热命中连续每周期接受一个请求、返回一个结果。
- 完成首次miss、重复hit、跨行、同组冲突、LRU、回填空拍、管理和复位测试。

源码：`rtl/cache_icache.v`；独立测试：`tb/icache_tb.v`。

### 2. CPU与缓存的统一握手

- 将原固定一拍存储器访问改为“地址接受＋实际完成”两阶段握手。
- 取指未返回时保存对应PC；跳转、异常或Cache管理后，已接受的旧取指响应排空并丢弃，不能当成新指令。
- load只有在结果真正到达后才离开EXE，随后由MEM做字节/半字扩展和前递。
- store只握手一次；等待期间不会重复写缓存或外设；更老指令未提交时不发出年轻store。
- 保留原算术逻辑、分支、乘除法、CSR、异常、ERTN、定时器及硬中断功能。

源码：`rtl/cpu/`；独立测试入口：`tests/run_cpu.py`。

### 3. 公共主存、仲裁和外设旁路

- I回填、D回填、D整行写回、I/D旁路共五个来源，共用一条逐字主存通路。
- 用轮转仲裁避免固定优先级饿死；一条缓存行传输完成后才切换来源。
- 把16B行拆成四个32位字，写回必须等第四个字的完成响应才向D-Cache确认。
- 对原 `bfaf_xxxx` / `1faf_xxxx` 外设区域旁路，不缓存、不读整行、不重复执行。
- 保留外设完整字节地址，避免把 `8001` 错当成原confreg的 `8000` 寄存器。
- 在课程板级缓存前归一化data_ram低18位地址镜像，保证 `0x100`、`0x40100` 等同一物理字的访问一致。
- 提供一拍同步SRAM桥、可初始化的块RAM描述、复用原confreg的SoC，以及CDP远程板顶层和引脚约束。

源码：`rtl/cache_subsystem.v`、`cache_mem_arbiter.v`、`cache_sram_bridge.v`、`cache_soc_lite_top.v`、`cache_board_ram.v`。

### 4. Cache管理指令

- 在真实CPU内译码并执行 `CACOP`，不是只预留一个管理接口。
- 支持I/D初始化、按索引无效化/写回无效化、按命中无效化/写回无效化，共六种code。
- 地址使用 `rj + 符号扩展si12`；不要求字对齐，也不把code当作GPR目的寄存器。
- 串行等待更老指令提交，完成后从本条PC+4重新取指，防止继续执行旧的预取内容。
- 对不支持的code报INE；非最高权限执行合法管理操作报IPE。
- 用实际D写代码→D写回→I无效→重新执行的程序验证自修改代码。

### 5. 集成、回归和文档

- 补齐独立模块、仲裁器、原confreg旁路、CPU变延迟、整机和原教师程序测试。
- 写独立ISA参考解释器，对照每一次寄存器写回和最终主存内容，不从待测CPU生成答案。
- 完成无缓存、直接映射、两路、四路的同程序/同延迟/等容量性能对比，保留缓存变慢的情况。
- 整理统一回归入口、可追溯源码哈希、教师输入哈希、Vivado工程准备脚本和上板检查步骤。
